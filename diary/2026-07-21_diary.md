# 2026-07-21 開発日記

## 実施したこと

- 公開されるレビュー画像とプロフィール画像に、画像の幅・高さ・総ピクセル数の上限を追加した。
- PNG、JPEG、WebPのヘッダーからデコード前に画像寸法を読み取り、最大4,096px四方かつ約13MPまでを受け付けるようにした。
- iPhoneの24MP/48MP写真も使えるよう、最大50MBの選択画像を端末内で縮小・圧縮してから2MBのAPI境界へ渡す共通処理を追加した。
- レビュー画像の表示を遅延読み込み・非同期デコードにし、一覧閲覧時に不要な画像を同時に展開しにくくした。
- 画像形式ごとの通常サイズ・上限超過を確認する回帰テストを追加し、`npm test`で実行できるようにした。

## 検証結果

- 画像寸法の回帰テスト: 4件成功。
- `npm run typecheck`: 成功。
- `npm run lint`: 成功。
- `npm run build -- --webpack`: 成功。
- `git diff --check`: 成功。
- 実装レビュー: 高解像度写真を縮小前に拒否する点を修正し、ブロッカーなしを確認。

## 判断と次回確認

- 4032 x 3024の一般的な12MP写真を受け入れつつ、圧縮後は小さくてもデコード時に大きなメモリを使う画像をアップロード前に拒否する。
- 投稿数・画像保存量のユーザー単位制限と、レビュー一覧のページネーションは、利用者数と運用コストのバランスを確認して別途実装する。
- 既にStorageへ保存済みの画像には今回の寸法制限は遡及しない。画像を完全にデコード・再エンコードする仕組みも、運用環境で必要になった段階で検討する。
